## ESP-IDF and the precompiled Wi-Fi library (StickS3 image)

The StickS3 image is built with ESP-IDF v5.4, commit `67c1de1eebe095d554d281952fde63c16ee2dca0`
(https://github.com/espressif/esp-idf, Apache License 2.0), and links Espressif's precompiled Wi-Fi
libraries from its submodule `components/esp_wifi/lib` (https://github.com/espressif/esp32-wifi-lib,
commit `a29b11bf0fe019ca0ade5459714b0b2426dfe020`, Apache License 2.0). Every build archive records the
SDK revision of each submodule (`sdk-submodules.txt`, `sdk-inputs/qualification.json`) and carries that
library licence (`sdk-inputs/LICENSE`).

Every SDK input is the vendor original. `firmware/boards/sticks3/tools/build_support.py` refuses to
build when any file in the SDK or its submodules differs from the pinned revision, and every archive
still records the sha256 of `esp32s3/libnet80211.a` (`toolchain.txt`) and keeps its bytes
(`sdk-inputs/libnet80211.a`).

**History: a modified Wi-Fi library until 2026-11-20** (G22 review finding P1; measured 2026-11-20):

| | `esp32s3/libnet80211.a` |
|---|---|
| pinned original (git blob `130bcf68718a6e456f76e53426dce85d59a511a1` of the submodule commit), read by every build since 2026-11-20 | 1,337,396 B, sha256 `5b90eb4f4553ba3479784470e186f3269fe1ea48acbe1c6fef23e4c7776b4ba9` |
| the modified file the builds read until 2026-11-20 on the owner's SDK install | 1,337,396 B, sha256 `5c9bb61b2cd1d45a500fde88f4ad7e147e4288bba96d9fafe2277db2301356d1` |
| difference | 4 bytes, all inside one function of the archive member `ieee80211_output.o`: `ieee80211_raw_frame_sanity_check` (section offset 95 of 508) |

- **What the function is.** It is the SDK's check on a frame handed to the raw transmit call
  `esp_wifi_80211_tx`. In the modified file the function returned "accepted" at that point, so the rest
  of the check did not run. [MEASURED: byte comparison of the two files and the object's section table.]
- **It was never in a Guardian image.** The Guardian sources never call the raw transmit call, so the
  linker dropped both functions: in the maps of the archived images they are listed under "Discarded
  input sections" with address 0 (`.text.ieee80211_raw_frame_sanity_check`, 0x1fc bytes, and
  `.text.esp_wifi_80211_tx`), and the images' symbol tables have neither name. [MEASURED on the archives
  `guardian-20261120-001058`, `guardian-20261120-005434` and `guardian-20261120-014618`; the two commands
  are in docs/G23-delivery.md.] The 4 changed bytes were therefore not
  in any image. [MEASURED 2026-11-20] The image built from the pinned original
  (`guardian-20261120-022200`) differs from the last image built from the modified file
  (`guardian-20261120-020722`) in 78 of 2,883,584 bytes, all in the app descriptor and the image
  trailer: version and build time, the embedded ELF hash, the IDF version string ("v5.4-dirty" became
  "v5.4"), and the checksum and appended hash; no code byte differs.
- **Where the change came from.** The file was already modified on the SDK install before this
  project started (file time 2026-11-02; the first ledger run is 2026-11-13). Who changed it and for
  which other project is not recorded here. The lab's test-stimulus firmware does not need it
  either; that firmware is kept outside the public repository.
- **Restored on 2026-11-20** on the owner's delegated decision:
  `git -C <idf>/components/esp_wifi/lib checkout -- esp32s3/libnet80211.a`, after which the file's
  sha256 is the pinned original's and `git status` in the submodule is empty. The allowance for the
  modified file was removed from `build_support.py` the same day. The modified bytes are kept by hash
  in the store (`$GUARDIAN_STORE/third-party/sdk-inputs/5c9bb61b…56d1-libnet80211.a`), so the change is
  reversible on the SDK install.

## Deflate decoding method (G21)

`firmware/adapters/companion/inflate.cpp` is this project's own raw-deflate inflater, written from RFC 1951
(the length, distance and code-length-order tables are the RFC's). Its canonical Huffman construction and the
bit-by-bit decode of long codes follow the method of `contrib/puff/puff.c` in zlib (Mark Adler, zlib license,
https://github.com/madler/zlib); no source text is copied and zlib is not linked into the firmware. The host
checks and `tools/face3d/pack_frames.py` use the system zlib only to produce and compare streams.
